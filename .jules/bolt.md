## 2024-05-19 - Recharts Geometry Types and React strictness
**Learning:** Recharts components can pass geometry props (`x`, `y`, `width`, `height`) as `string` or `number` or `undefined` depending on calculation context, which breaks strict TypeScript validations on custom `<Label />` inline math (`x + width / 2`). Furthermore, passing inline configuration objects like `margin={{ top: 20... }}` directly to Recharts or dynamically mapping array data (`quizData`, `heatmapData`) without `useMemo` triggers expensive full SVG layout recalculations on every render due to broken reference equality.
**Action:** Extract static Recharts `margin` and `padding` objects outside React components. Always wrap data arrays mapped from props in `useMemo`. Explicitly safely coerce (`Number(x) || 0`) custom label geometric properties before performing arithmetic.
